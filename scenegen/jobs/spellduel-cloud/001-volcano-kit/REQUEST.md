# 生成器工單 001：炎之山的 3D 地形零件包（火山）

- **發單**：SpellDuel 遊戲端（雲端 Claude Code session）
- **執行**：本機的場景生成器 session（`E:\AI接案\rpg-world-builder`，`control.py`）
- **工單資料夾**：`scenegen/jobs/spellduel-cloud/001-volcano-kit/`
  - 這份需求：`REQUEST.md`、`request.json`
  - 執行端寫回：`response.json`、`inspect.json`、`previews/`
- **成果放到**：`spellduel-unity/Assets/SpellDuel/Resources/SceneKit/volcano/`

## 這是要做什麼

SpellDuel 第一大關「炎之山」（`ch1_volcano`）的地圖是**遊戲裡用程式即時產生的**：格子、走道、區域、門、障礙物的位置都是程式算的，**這部分不改**。

要請生成器做的是**擺在這些位置上的 3D 外觀零件**：岩壁、轉角、岩門、障礙物、噴口、岩洞入口、遠方的大岩塊。

- 遊戲會照程式算出的格子，把零件一個一個擺上去。
- 每種零件只做一次，整張地圖重複使用。
- **不要做一整張固定的地圖。**

風格照生成器現在的設定：
- 自然火山地形：凝固熔岩、火山灰、曲面岩岸、岩洞入口。
- 不要鋪磚，不要觀光平台。

## 遊戲的尺寸（零件要對齊這些）

| 項目 | 數值 |
|---|---|
| 格子 | **1 格 = 4m × 4m**，地圖是格子組成的 |
| 走道 | 寬 1 格（4m），會轉彎 |
| 戰鬥區域 | 5×5 格（20m × 20m）；首領區域 7×7 格（28m × 28m） |
| 門 | 在區域邊上佔 1 格；清完區域才打開 |
| 玩家 | 眼睛約離地 1.5m；AR 遊戲，玩家用身體走路，鏡頭就在玩家頭上 |
| 地面 | 遊戲自己鋪手繪地面圖。**零件不用做地板**，只做「地面以上」的東西；底部可以帶一點跟地面接合的岩岸、碎石 |

**座標**
- 單位公尺，Y 朝上，+Z 是前方，跟 Unity 一樣。
- 零件的原點（pivot）放在**底部、貼著地面**。

## 要做的零件

每種至少 **3 個不同的版本**（`_a`、`_b`、`_c`），避免整條路看起來都一樣。

| id | 尺寸（寬 × 深 × 高） | 內容 | 原點、方向 |
|---|---|---|---|
| `wall_straight` | 4 × 1.5～2.5 × 3～5m | 一格長的岩壁（凝固熔岩、層狀岩），沿著走道和區域的邊 | 原點在牆腳中間；**可以走的那一面朝 +Z**；左右兩端（x = ±2m）要能和下一塊接得自然（可以稍微重疊） |
| `wall_corner_out` | 約 2 × 2 × 3～5m | 外轉角（凸出去的角） | 原點在轉角；兩面分別朝 +Z、+X |
| `wall_corner_in` | 約 2 × 2 × 3～5m | 內轉角（凹進來的角） | 同上 |
| `wall_end` | 約 1.5 × 2 × 3～5m | 岩壁的盡頭（收尾） | 原點在牆腳中間 |
| `gate_frame` + `gate_door` | 4 × 1.5 × 4.5m | 岩門：**門框一個模型、門板另一個模型**（遊戲會讓門板下沉或往旁邊滑開） | 門框原點在中間；門板原點在底部中間，關著時剛好塞住門框 |
| `ob_jump` | 3.8 × 0.8 × 0.35～0.45m | 要跳過的：橫躺的岩脊、冷卻的熔岩堆 | 原點在中間；橫跨 X 方向 |
| `ob_duck` | 3.8 × 0.8 × 2.2m | 要蹲下鑽過的：兩邊岩柱撐著一條橫的岩梁 | **岩梁底邊在 1.30m**（遊戲會照玩家身高把整個零件在 Y 方向縮放 0.85～1.15 倍）；岩梁以下要完全空出來 |
| `ob_side` | 2 × 1.2 × 1.8～2.2m | 要往旁邊閃的：崩落的巨石堆，擋住半條路 | 原點在擋住的那半邊中間；遊戲會左右翻轉使用 |
| `vent` | 1.4 × 1.4 × 0.2m | 岩漿噴口：焦黑的火山口 | 中間的熔岩用**單獨的子物件**（`vent_core`），遊戲會讓它發光、閃爍 |
| `cave_entrance` | 約 12 × 6 × 8m | 首領區域的岩洞入口（只要 1 個版本） | 原點在洞口底部中間，洞口朝 +Z |
| `backdrop_rock` | 10～25m 高 | 遠方的大岩塊、火山錐，擺在地圖外圈當背景（3 個版本） | 原點在底部中間；背面不會被看到，可以不做 |
| `exit_altar` | 2.8 × 2.8 × 0.5m | 脫出點的底座：一圈矮石柱圍著一塊平台（1 個版本） | 原點在中間；中間要平，遊戲會疊藍色魔法陣 |

煙雲動畫生成器已經有了，請保留，另外輸出：
- 一個火山煙柱的序列圖或動畫。
- 格式照生成器現有的就好，在 `response.json` 寫清楚怎麼用。

## 技術規格（很重要）

- **遊戲是 Unity 2022.3、內建渲染管線（不是 URP）。**
  - 請不要附 URP 材質或 URP shader，不然匯入會變粉紅色。
  - 只要模型＋貼圖，材質由遊戲端用程式配。
- **模型格式**：FBX（優先）或 OBJ。單位公尺，匯入時比例 1:1（Blender 匯出用 Apply Unit／Apply Transform，前方 -Z、上方 Y 的 Unity 預設）。
- **面數上限**（手機 AR，要很省）：

  | 零件 | 三角形 |
  |---|---|
  | 岩壁、轉角、牆尾 | 每個 ≤ 600 |
  | 障礙物、噴口、脫出點 | 每個 ≤ 800 |
  | 岩門（門框加門板） | ≤ 1,200 |
  | 岩洞入口 | ≤ 3,000 |
  | 遠景大岩塊 | ≤ 1,500 |

  不需要 LOD。
- **貼圖**：
  - 整包零件**共用一張 2048×2048 的顏色圖集**（`volcano_kit_albedo.png`，sRGB）。這樣遊戲可以合併繪製、不會變慢。
  - 陰影、凹凸、縫隙的暗部（AO）**直接烘進顏色圖**：遊戲不用法線貼圖。
  - 熔岩的發光部分另外一張 1024×1024 的發光遮罩（`volcano_kit_emissive.png`，黑底，發光的地方亮）。
  - UV 不要超出 0～1。
- **顏色**：
  - 要跟遊戲現有的手繪地面 `Resources/StageArt/volcano_0_ground.png` 放在一起協調：焦黑的玄武岩、暗紅褐色、橘紅發光的裂縫。
  - 光源在左上方。
  - 偏手繪風（日式動畫奇幻），不要寫實照片質感。
- **不要附 Unity 的 `.meta` 檔**，遊戲端會自己設匯入設定。
- 總檔案大小盡量 ≤ 15MB（不含預覽圖）。
