## 驗證方法與限制

執行 `python spellduel-unity/Tools/check_ui_skill_polish.py --native --require-mobile`，檢查來源、交付尺寸／張數、快取稽核與平台建置證據。需要 Python Pillow。

按鈕／NextTag／Toggle 的完整呼叫表達式與原始來源比對；UiLock、Walkthrough、Dash 不變。Claude 同時更新的城鎮／地圖檔使用 `c41e792` 作比較基準，其餘使用 `5a4a0bf`。受保護戰鬥、技能、製造、探索與語音來源未修改。

原生 FX 稽核檢查共用可讀性元件重複更新時不增加貼圖／材質，並驗證近視角、命中收尾和容量。圖示稽核在 Unity 中比對重複輸出與 253 次快取命中。所有技能的資料範圍列在稽核中；三階段截圖抽驗 48 招，不代表逐一完成所有技能的實機操作測試。

原生 UI 是停用 AR／連線啟動的展示場景，使用正式繪圖函式與固定樣本資料；亮暗背景是可讀性測試底色。沒有以重繪概念圖冒充遊戲截圖。城鎮原圖可水平拖曳，畫面邊緣的地點標籤裁切沿用既有行為。

未完成的實機驗收：中階 Android 60fps、真實 AR 相機背景、多人六大招同場及手機觸控／教學操作。數量上限與編譯成功不能取代上述實測。TestFlight 發布不列入本次編譯驗收。

## 原生數量結果

最終 FX run `41241105571`（`8121b87`）：288 張階段畫面，單一樣本最大粒子容量 144、網格與線段保守面數上界 3,536。六種大招彈道視覺根同場容量為 81 粒子、6,862 面；此畫面是彈道元件組合，並非六名玩家完整戰鬥的負載測試。上限分別為每 root 192 粒子、每粒子系統 64；三階段測試門檻 576 粒子／24,000 面，六招組合門檻 3,456／144,000。

同步說明：`0199549` 合併 Claude 的工匠／藥劑師材料來源提示（`af05a5b`）。此三個檔案的互動比對使用該合併基準，保留新增提示；靜態外觀與本次預覽相同。平台證據可使用包含 `8121b87` 的後續合併，檢查器另確認 FX 來源沒有再變動。

特效預覽是正式工廠函式的分階段視覺樣本；複合招式展示其中的彈道／施放元件，沒有啟動戰鬥事件重演全部追加彈、召喚物或持續區域。因此應配合遊戲內完整施放確認，不把此圖當成完整招式時序錄影。`C/overview_*.jpg` 為方便檢視的縮圖索引。

後續同步：Claude 的 `cdf38c4` 探索地面、`20ac20b`／`8cdbb89` 等級上限、`7d95bef`／`762b838` 難度平衡均保留。受保護來源的零變更檢查固定使用美術交付 `8121b87`，避免把後續平衡修改誤算為本輪美術修改。完整平台編譯來源以 platform_ci.json 為準。

驗證範圍補充：由於玩法分支持續同時更新，受保護程式的零變更稽核固定檢查美術交付 `8121b87`，不限制後續由其他工作加入的平衡變更。介面呼叫、快取／圖片、CI證據仍按各自記錄檢查；本輪沒有修改 Combat。

平台使用獨立 `spellduel-art-compile.yml`：每個提交的驗證互不取消，只產生APK／IPA，沒有Release與TestFlight發布工作。原發布流程保持不變。
