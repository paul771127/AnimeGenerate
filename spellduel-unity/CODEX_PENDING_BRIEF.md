# Codex 總單：目前還沒交付的美術與畫面

這張單把目前還沒做的 Codex 工作集中在一起，依優先順序排列。每一項做完，就在本檔最後的「Codex 實作紀錄」寫下做了什麼、檔案放在哪裡。

**共通規則**
- Unity 2022.3：Android 與 iOS 都要編譯通過。
- 不要改戰鬥邏輯、數值、存檔格式和網路訊息。只做美術，以及把美術接到現有的入口。
- 2D 圖的畫風、解析度、檔名規則，沿用 `Resources/Village2D/`（城鎮）和 `Resources/Story2D/chars/`（立繪）裡現有的檔案。
- 預覽圖放在 `Docs/pending_preview/`。

## 1. 城鎮新建築：⚗ 藥劑師、🛠 工匠（最優先）

功能已經做好了（`WorldUI.Craft.cs`、`Crafting.cs`）。現在的入口只是兩顆暫時的按鈕：
- 道具店裡的「⚗ 藥劑師」：`WorldUI.Shop2D.cs`，`Design(40,1360,600,95)`
- 鐵匠鋪裡的「🛠 工匠」：`WorldUI.Smith2D.cs`，`D(40,1520,600,100)`

要把它們做成城鎮地圖上真正的建築。

### 1-1 城鎮地圖（5 個城鎮都要）

1. 在 `map_flame`、`map_forest`、`map_harbor`、`map_desert`、`map_snow` 的 png、`_fit.png` 和 json 各加兩棟建築。
   - json 的 key 是 `alchemist` 和 `crafter`，格式和現有的 `smith`、`shop` 一樣（x/y/w/h/label_x/label_y）。
   - 新建築不能壓到現有建築，標籤也不能和現有標籤重疊。
2. 在 `WorldUI.TownMap.cs` 裡：
   - `MapSites` 加上 `["alchemist"] = ("⚗ 藥劑師", 紫色)` 和 `["crafter"] = ("🛠 工匠", 金色)`。
   - 點擊的 switch 加兩個 case：`alchemist` 開 `Screen.Alchemy`，`crafter` 開 `Screen.Craft`，順便清掉 `craftSel` 和 `craftScroll`。
3. 建築外觀要配合各城鎮的主題：
   - 藥劑師：煉藥小屋，有冒煙的大鍋、藥草和瓶罐。
   - 工匠：工坊，有工作台、零件和設計圖。看起來要和現有的鐵匠鋪有明顯差別，不要只是另一間打鐵舖。

### 1-2 室內畫面（照 Shop2D、Smith2D 的做法）

1. 室內背景圖：`in_alchemist_<town>.jpg`、`in_crafter_<town>.jpg`。
   - 至少要有 flame 版。`FacilityBg` 目前只讀 `_flame`，可以改成先讀當地城鎮的版本，找不到再用 flame。
2. NPC 立繪：每人至少 normal、smile、serious 三種表情。
   - 藥劑師（每個城鎮一位，名字已經寫在 `WorldUI.Craft.cs` 的 `AlchemistNames`）：
     - 炭火鎮：藥婆婆・炭姨
     - 森林：藥師・青蘿
     - 港口：藥商・汐
     - 沙漠：藥劑官・賽琳
     - 雪原：旅藥師・駝鈴
   - 工匠：工匠・老錘（5 個城鎮是同一人，到處跑的老工匠）。
3. 把 `DrawAlchemy` 和 `DrawCraft` 改用 `Facility2DFrame` 呈現，也就是背景、NPC 立繪和台詞框。清單、製作按鈕和材料區沿用現有邏輯。
   - 台詞：仿照 `lines_shop.txt` 新增 `lines_alchemist.txt` 和 `lines_crafter.txt`，分成打招呼、做好了、材料不夠、做出高品質四組，每組 3～5 句。
4. 製作動畫（簡單即可）：
   - 藥劑師按「製作」：大鍋冒泡約 1 秒，變色後跳出藥瓶。
   - 工匠按「製作」：做好時發光，依稀有度變色。可以參考鐵匠的 anvil_0～5。
5. 拿掉 Shop2D 和 Smith2D 裡那兩顆暫時按鈕。新手指引不能因此壞掉（`UiLock` 的步驟沒有指向它們）。

### 1-3 圖示

- 10 種強化藥劑：`bp_str` 力量、`bp_eye` 鷹眼、`bp_regen` 再生、`bp_swift` 迅捷、`bp_wise` 智慧、`bp_ward` 抗魔、`bp_blood` 嗜血、`bp_iron` 鐵壁、`bp_vigor` 活力、`bp_wind` 疾風。

## 10. 副本多人版玩法（程式工作：這一項例外，可以改 `Combat.RoomEvents.cs` 和 `SoloBattle.RoomEvents.cs`）

單人時規則不變，2 人以上才切換成多人版。由房主判定，用現有的 `rev`、`reve`、`evsay` 訊息同步，需要的話可以加欄位。已經做好的：守護物和護送 NPC 的血量 ×人數、圖騰每多一人多一根、撐住每多一人 +10 秒、最後的菁英數＝人數。

還要做的：

**資訊分散**：每支手機只看到一部分，要互相講。
- 符文順序：順序的每一步只在一位玩家的手機上亮，輪流分配。
- 咒語之門：謎題拆成幾段線索，每支手機只顯示自己的那段；答案誰唸都算。
- 找出真身：真寶箱的閃光每次只有一位玩家看得到，輪流換人。

**同時行動**
- 封印圖騰：圖騰互相連結，最後一根倒下前 5 秒內要全部打倒，否則先倒的會復活。
- 對應元素：多一座「雙屬性」雕像，要兩個不同屬性在 3 秒內一起打中才算。
- 斬首：目標數＝人數，全部要在 5 秒內打倒，否則先倒的會復活。

**分頭行動**
- 守住目標：2 人以上時，場地兩邊各一個守護物，任一個被打壞就失敗。
- 護送：路上隨機出現路障，要打掉 NPC 才能繼續走；有人去打路障時，其他人留在 NPC 旁邊擋怪。
- 黑暗房：每位玩家身邊 2.5m 是亮的，任何一個人照到的怪，全隊都看得見。
- 崩塌：裂縫優先出現在玩家擠在一起的地方。

請一起補上測試，放在 `Docs/` 或 `tools/` 都可以，至少要模擬 2 人和 3 人的情況，確認多人版的過關、失敗和懲罰都正確。

## 12. 敵人的攻擊招式：設計提案（使用者覺得目前有點單調）

先出**設計提案**，不要直接改戰鬥邏輯。寫在 `Docs/ENEMY_MOVES_PROPOSAL.md`，確認後由我接進 `Combat.cs`。

現況：大部分小怪一種招式——近戰「預備 → 扇形爪擊」、遠程「瞄準 → 直線射一發」、衝鋒獸「刨地 → 直線衝」，另外有拋物線（毒液、巨石）、地上藤蔓、水母放電、河豚刺球。菁英怪有 Sweep、Quake、Line、Burst、Summon、Heal、Shield 七種（`EliteCatalog.cs`）。

提案內容：
1. 每一種一般小怪（0～18）和特殊敵人（19～22）各提 1～2 個**第二招**，讓同一隻怪不會每次都同一個動作。例如：
   - 熔岩小鬼：連續兩下爪擊；或往旁邊跳開再撲過來。
   - 火焰射手：三連射扇形；或打在地上留下燒地。
   - 衝鋒獸：衝完回頭再衝一次（Z 字形）。
   - 食人花：從地下換位置冒出來。
2. 每一招都要寫：
   - 觸發條件：距離、血量、冷卻、跟哪幾隻怪一起時。
   - 預警：玩家要看到什麼、有多久時間反應。
   - 躲法：跳、蹲、側步、離開圈。這個遊戲是 AR 體感，躲法要能用身體做到。
   - 傷害倍率（相對原本那一招）。
3. **組合招**：兩三種怪一起時的配合。例如前排小鬼把人逼到一邊、後排射手封另一邊；補師幫衝鋒獸加速。
4. 第 4、5 章要比前面章節更有壓迫感，但每一招都要有明確的預警，不能是「看不到就被打」。
5. 每一招附一張示意圖或一段動作描述，放在 `Docs/pending_preview/enemy_moves/`。

## 14. 寵物系統（設計提案＋美術）

使用者要的新系統：玩家用特殊物品當誘餌，引誘對應的怪物、收服成寵物；寵物陪玩家戰鬥，有等級、會放技能；餵飼料有機率學會新技能。

**已經定好的規則**（設計請照這個走）：
1. **收服方式**：
   - 戰鬥中丟出對應那種怪的誘餌，那種怪會被吸引過去吃，約 3 秒，這段時間不攻擊。
   - 吃餌時把牠打到 30% 以下 HP，就會擲收服。血越低、幸運越高越容易成功；失敗就掙脫，誘餌用掉。
2. **一場只帶 1 隻寵物出戰**；寵物可以養很多隻，在角色畫面切換出戰的那隻。
3. **寵物在戰鬥中倒下，這一場就不能再出**，下一場才回來。
4. **可收服的範圍**：
   - 一般小怪（第 1～5 章，0～18 號）和菁英（23～47 號）。
   - 菁英的誘餌很稀有、收服比較難，寵物也比較強。
   - Boss、特殊敵人（19～22）、補師、召喚師、刺客、天候怪、寶箱怪不能收。
5. **寵物有等級**：跟著出戰拿經驗，能力隨等級成長；會自動攻擊、自動放技能。
6. **餵飼料**：每次餵食加經驗，並有機率學會新技能。每隻寵物的技能有上限。

**現有可以沿用的東西**（給你參考，邏輯由 Claude 接）：
- 召喚師的「魔物捕捉」（`Combat.Npc.cs` 的 `Capture`）：會把小怪變成友方單位（`SpawnNpc`＋`tamedKind`），在戰場上自動戰鬥，合作時也會同步給隊友（`localFriend`）。寵物出戰會沿用這套。
- 小怪模型：`MinionRig`；菁英：`MinionRig.Elite.cs`。

**請 Codex 做：**
1. **設計提案** `Docs/PET_SYSTEM_PROPOSAL.md`：
   - **誘餌表**：每種可收服的怪對應哪一種誘餌——名字、取得方式（掉落、商店、調配）、價格或掉落率。菁英的誘餌要稀有。
   - **寵物成長**：等級上限、每級的 HP／攻擊成長、出戰拿多少經驗；菁英寵物比一般寵物強多少。
   - **技能**：
     - 每種寵物一開始會的招式。
     - 可以學的技能池，每種 3～5 招，依種族或屬性分組。
     - 每招寫效果、冷卻、數值建議。
     - 每隻最多學幾招，學滿了怎麼辦（例如可以遺忘）。
   - **飼料**：2～3 種（普通、高級……）——取得方式、加多少經驗、學新技能的機率。
   - **畫面流程**：角色畫面的「🐾 寵物」分頁（寵物列表、等級、技能、餵食、設為出戰），戰鬥中丟誘餌的按鈕與提示。
   - 示意圖放在 `Docs/pending_preview/pets/`。
2. **美術**：
   - 寵物版外觀：沿用那隻怪的模型，加上一眼看出是「我方寵物」的配件，例如項圈、緞帶，腳下有友方光圈。菁英寵物要更顯眼。
   - 吃誘餌的動作；收服成功、失敗的特效。
   - 誘餌、飼料的圖示，照 `SkillIcons.Supplies.cs` 的素材圖示畫風。誘餌可以依章節或種族分組，不一定每種怪一張。
   - 寵物分頁的版面設計。
3. **分工**：寵物的戰鬥邏輯、收服判定、存檔、數值、技能效果由 Claude 照你的提案實作；你不用改戰鬥邏輯。

先交設計提案，確認後再做美術。
