# 劇情優化＋說話者頭像（給 Codex）

使用者的要求：**劇情再優化，要有連貫性、帶入感；對話框旁邊要有說話者的頭像與名稱。**
對話框的版面（頭像在左、名字在頭像下、台詞在右）Claude 已經做好；這份文件列出要 Codex 做的**文字與美術**。

## 1. 劇情（`Assets/SpellDuel/Resources/story.txt`，格式見 [`STORY_FORMAT.md`](STORY_FORMAT.md)）

目前是三章各四關的主線「獻給黎明的三重奏」（熔岩 → 森林 → 海上）。請重寫／潤飾，目標：

- **連貫性**：
  - 三章是同一條故事線：每一章結尾留下通往下一章的理由（線索、人物、未解的謎），下一章開頭要接得上。
  - 同一個角色的說話口吻、稱呼、知道的事要前後一致。
  - 城鎮居民（`Runtime/WorldUI.cs` 的 `Towns` → `npcs`）、轉職試煉的公會長台詞（`Runtime/SoloBattle.cs` 的 `StartTrial()`）也要和主線呼應。
  - 居民的台詞最好會隨主線進度改變（如果要這樣做，請告訴 Claude，由 Claude 加「依通關進度切換台詞」的程式）。
- **帶入感**：
  - 主角就是玩家：用 `{玩家}` 稱呼。不要假設主角是哪個職業，也不要替主角說太多話。
  - 每關開戰前要讓玩家知道「為什麼要打這一仗、打贏會怎樣」。
  - 打完要有回饋：誰得救了、世界有什麼改變。
  - 每章有一兩個情緒起伏，例如同伴受傷、背叛、犧牲、重逢。
  - Boss 要有動機：開戰前和倒下時各說一兩句。
- **長度**：
  - 每句 60 字以內（手機直式）。
  - 每關 `<before>` 約 4～8 句，`<after>` 約 2～5 句。
  - 旁白不要一次連續太多句。
- **不要改**：關卡的 `theme`、`waves`、`req` 與關卡編號（存檔用編號記通關）；可以改標題、簡介、`xp`。

## 2. 說話者頭像（`Runtime/Portraits.cs`）

**現在的狀況：**
- 每個說話者都用「預設頭像」：名牌顏色的圓角方框＋半身剪影。
- 居民名字「村長・老焰」會自動對應到劇本裡的「老焰」，共用同一張頭像。

**要做的：** 為每個有名字的角色畫**專屬頭像**。
- 在 `Render()` 的 `switch` 加上 `case "名字": 畫法(px, size); return px;`。
- 純程式繪製，不能用圖檔。可以參考 `SkillIcons.cs` 的有向距離場畫法，同樣做反鋸齒。
- 風格：日式賽璐珞（見 [`ART_STYLE.md`](ART_STYLE.md)）。
- 構圖：胸像，臉要有特色。可以從這些地方區分：
  - 髮型、髮色
  - 眼睛
  - 配件（帽子、眼罩、耳環…）
  - 服裝的領口
- 外框沿用圓角方框，邊框顏色用名牌色（`Story.TagColor`）。

## 3. 驗收
- 劇本格式錯誤會在遊戲裡列出；請確認 `Story.errors` 是空的。
- 如果有工具，產生 `docs/portraits.png` 預覽：所有頭像排成一張圖。
- iOS／Android 都要能編譯（Claude 會再檢查與建置）。
- 不要動 `Battle`／`Fighter`／網路程式；只改 `story.txt`、`Portraits.cs`、`WorldUI.cs` 的居民台詞、`StartTrial()` 的台詞。
