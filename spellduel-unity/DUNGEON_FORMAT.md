# 副本劇本格式與量產流程（給 Codex／編劇／自動化腳本）

副本只有一個檔案：`spellduel-unity/Assets/SpellDuel/Resources/dungeons.txt`（UTF-8 純文字）。
遊戲第一次用到副本時讀取這個檔案。**新增副本只要在檔案後面加一個 `[dungeon]` 區塊，不用改程式。**

改完一定要跑檢查：

```
python3 spellduel-unity/Tools/check_dungeons.py
```

沒有錯誤才提交。遊戲裡的解析器是 `Dungeons.Parse`，規則和這支檢查腳本相同。

---

## 1. 格式

```
[dungeon 英文id] 副本名稱
一兩句簡介（顯示在副本入口的清單）。
level = 12          # 副本等級：掉落的物品等級、難度基準
players = 2-4       # 建議人數（選填，預設 2-4）
unlock = 1-2        # 要先通關的故事關卡 id（選填；不寫＝一開始就開放）
<before>            # 開場劇情：單人第一次進入時是對話框，多人時是戰鬥中的字幕卡
旁白：……
老焰：……
<after>             # 通關劇情（第一次通關時播放）
旁白：……

[room] 房間名稱
wave = 7            # 這個房間打第幾波：決定敵人強度與種類
theme = volcano     # 選填：指定場景（volcano／forest／sea／arena／canyon）；不寫＝照波次
<enter>             # 進房間時的字幕卡（戰鬥不暫停，依字數自動換下一句）
旁白：……
小鐵：……
<clear>             # 清完這個房間時的字幕卡（選填）
小鐵：……
<boss_half>         # 首領剩一半血時的字幕卡（選填，只有首領房有用）
熔岩巨像（boss）：……
```

### 規則
- 一行一筆。空行、`#` 或 `//` 開頭的行會被忽略。
- `[dungeon]` 的 id 只能用英文、數字、底線，而且不能重複。這個 id 會寫進存檔（通關紀錄），之後不要再改。
- 每個副本至少 2 個房間，**最後一個房間一定是首領**（`wave` 是 10 的倍數；地圖副本見 1-2）。
- 每個副本都要有 `<before>` 和 `<after>`；每個房間都要有 `<enter>`。
- 台詞格式和故事劇本一樣：`說話的人：台詞`。說話的人後面可以加（標記）決定名牌顏色，`（boss）` 是紅色；沒有冒號，或寫「旁白」，就是旁白；`{玩家}` 會換成玩家的職業名稱。
- **每句 60 字以內**（手機直式的字幕卡）。長的請拆成兩句。
- `<enter>` 建議 1～3 句，`<clear>` 和 `<boss_half>` 各 1～2 句。戰鬥中玩家沒空讀長文。

### 1-2. 固定地圖（房主選路線）

把 `[room]` 換成 `[node 地點id] 地點名稱`，再用 `next =` 寫「打完可以去哪裡」，就是有分岔的地圖：

```
[node tunnel] 崩落坑道
wave = 7
next = fungus, rails      # 打完由房主選：菌林 或 廢軌道（只有一條路就 4 秒後自動走）
npc = foreman             # 走進這裡時登場的劇情人物（[npc] 的 id，可以寫多個）
<enter>
……

[node locker] 礦工的置物箱
event = chest             # 寶箱地點：不用打，打開就有獎勵
next = hall
<enter>
……

[node boss] 首領：熔岩巨像
wave = 10                 # 沒有 next 的地點＝終點，一定要是首領
```

- `event`：`battle`（預設，戰鬥）、`chest`（寶箱）、`boss`（首領；`wave` 是 10 的倍數的戰鬥會自動當首領）。
- **特殊地點**（`event =` 下面這些；強度仍照 `wave`，和一般戰鬥一樣算進「6～9 場一般戰鬥」）：

| event | 玩法 | 過關 | 失敗／懲罰 | 可以寫的設定 |
|---|---|---|---|---|
| `defend` | 場地中央的守護物（有血條），小怪優先打它 | 清完這一波 | 守護物被打壞＝副本失敗 | `name`、`hp`（預設 900）、`fail` |
| `survive` | 怪不停湧出、更痛；最後 10 秒出一隻菁英 | 撐過時間 | — | `time`（秒，預設 30） |
| `escort` | NPC 沿著場內繞 240° 走到出口；有怪貼近就停下 | 走到出口 | NPC 倒下＝副本失敗 | `name`、`look`、`hp`（預設 500）、`fail` |
| `hunt` | 一隻菁英目標＋不斷湧出的怪（打倒一隻 3 秒後補一隻）；45 秒起每 30 秒叫援軍 | 打倒目標 | — | — |
| `totems` | 場邊的封印圖騰每 6.5 秒叫怪 | 圖騰、怪都清完 | — | `count`（2～5，預設 3）、`hp`（預設 260） |
| `runes` | 地上的符文照順序亮一遍，照順序踩上去 | 踩完整個順序 | 踩錯：出一群怪，越錯越多越強，打完重看 | `count`（3～6，預設 4）、`seq`（順序長度，預設 3） |
| `chant` | 用語音唸出謎題的答案（錯過一次後顯示提示） | 唸對 | 唸錯：出一群怪，越錯越多越強 | `riddle`、`answer`（2～4 字，不要和技能名稱一樣）、`hint`；不寫就從內建謎題挑 |
| `elements` | 三座雕像各要火／冰／雷，用對的屬性打；場邊的屬性球讓全隊下一擊帶那個屬性（12 秒） | 三座都點亮 | 打錯：出一群怪，越錯越多越強 | — |
| `mimic` | 幾個寶箱只有一個是真的（真的會偶爾閃一下，靠近時手機輕震） | 打開真的 | 打錯：變成寶箱怪，越錯越強 | `count`（3～7，預設 5） |
| `collapse` | 地面一格一格塌陷（先紅框 2 秒），站在裂縫上每秒扣 8% HP | 清完這一波 | — | — |
| `dark` | 一片漆黑，2.5m 外的怪只看得到發光的眼睛 | 清完這一波 | — | — |

  - 特殊地點的 `<enter>` 請用一句話說明玩法（例如「守住它！」「照順序踩上去」）。
  - 不要和劇情人物（`npc =`）放在同一個地點。
  - 範例：灰燼礦坑的廢棄軌道（escort）、餘燼鑄鐘坊（collapse／elements／defend／chant）、霧燈記名徑（runes／chant／dark／totems）、白帆回聲礁（mimic／hunt／survive／defend）。
- **第一個地點是起點**（不能是寶箱）。每條路最後都要走到首領；不能繞圈；每個地點都要走得到。
- 有任何地點寫了 `next` 就是地圖副本；都沒寫就是舊的線性副本（照檔案順序一間一間打）。
- 換地點時場景跟著換成那個地點的主題（`theme`，或照 `wave`）；寶箱沒寫 `theme` 就沿用上一個地點的場景。
- **寶箱**：每個人各拿一件稀有以下的裝備＋金幣；45% 的機率還有一件**史詩以上**的大獎 → 每個人選「🎲 擲骰」或「🙅 放棄」（20 秒），擲 1～100 點數最大的拿走，最大點平手的人重擲。單人直接拿。收集型任務也會 +1。
- 新副本每條通關路線需先打 6～9 場一般戰鬥，再進入最後的首領；寶箱、對話與首領戰不算一般戰鬥。地點總數可超過 7 個，分岔不能形成少於 6 場戰鬥的捷徑。
- 各副本可選不同特色：護送、抉擇、收集或航路探索等，不必每個副本都塞入所有要素。

### 1-3. 劇情人物 `[npc]`

```
[npc ayan] 受困的礦工阿岩
role = escort             # escort 保護目標／choice 抉擇／quest 任務
look = swordsman          # 外觀（mage／archer／swordsman／priest／assassin）；劍士、刺客近身砍，其他射普攻
hp = 500                  # 血量基準（實際會照波次變強）
until = boss              # 保護目標：抵達這個地點就安全了（不寫＝撐到通關）
<meet>                    # 登場台詞（必填）
阿岩：救、救命！……
<safe>                    # 抵達 until 的地點
<die>                     # 倒下時
```

| role | 在戰場上 | 怎麼寫 |
|---|---|---|
| `escort` 保護目標 | 跟在玩家旁邊、不出手；**小怪會優先撲向他**。倒下＝**副本失敗**，大家退出副本 | `hp`（300～600）、`until`、`<meet>`／`<safe>`／`<die>` |
| `choice` 抉擇 | 登場時戰鬥先暫停，**房主**從選項裡選一個：`ally` 變友軍（幫忙打怪、跟著隊伍到最後）、`enemy` 變敵人（和小怪一起打玩家，要打倒才算清完這個地點）、`third` 第三勢力（誰都打、誰都打他，這個地點打完就撤退） | `option = 選項文字 -> ally／enemy／third`（2～3 個）、`hp`（150～250；當敵人時會再乘上敵人倍率）、`<meet>`／`<ally>`／`<enemy>`／`<third>`／`<die>` |
| `quest` 任務 | 不上場，只在對話窗說話；右上角顯示任務進度，完成給獎勵 | `goal = kill 8`（打倒 8 隻敵人）／`goal = collect 3 礦工的名牌`（每打倒一隻 30% 掉一個、寶箱必給一個）／`goal = reach hall`（走到某個地點）；`reward = gold 400` 或 `reward = item 3`（每人一件這個稀有度：1 優良～4 傳說）；`<meet>`／`<done>` |

- 人物只在**寫了 `npc = id` 的地點**登場，所以可以放在「某條岔路才遇得到」的地方。
- 人物的台詞在 `<meet>` 這些區塊裡；**`option`、`goal` 這些設定寫在台詞後面也可以**（英文 key = 值 的行會結束上面的台詞區塊）。

### 1-4. 對話窗

副本裡左下角有對話窗（按 💬 切換：關、1～5 行，文字背後透明）。會顯示：劇情台詞（說話的人＋台詞）、事件（來到某地點、寶箱、擲骰結果、任務完成），以及**大家說的話**（語音辨識到的文字，連線時隊友也看得到）。

## 2. 數值怎麼選（量產時照這張表）

敵人強度只看 **`wave`**：每一波 HP +3.5%、攻擊 +2%。另外副本的敵人血量、攻擊固定 ×2，數量與首領血量再乘上人數（最少 ×2）。

| 副本等級 `level` | 一般房間的 `wave` | 首領房 `wave` | 首領（照主題） |
|---|---|---|---|
| 8～14 | 5～13 | 10 | 熔岩巨像 |
| 15～24 | 12～19 | 20 | 腐化樹王 |
| 25～34 | 21～29 | 30 | 深淵海妖 |
| 35～44 | 31～39 | 40 | 青銅鬥魂（角鬥場） |
| 45～54 | 41～49 | 50 | 黃土岩魔（山道） |
| 55 以上 | 51 以上（主題重新輪一次） | 60、70… | 照主題 |

- **主題（場景、小怪種類）**：照波次決定，第 1～10 波熔岩、11～20 森林、21～30 海上、31～40 角鬥場、41～50 山道，51 波起重新輪一次。
- **想要跨主題**（例如海底王城裡出現熔岩庫房）：用高一點的波次維持強度，再加 `theme = volcano` 換場景。範例見 `sunken_throne` 的「被燒乾的庫房」。
- **房間數**：依路線安排，所有通關路線須有 6～9 場一般戰鬥＋最後的首領。寶箱另計，分岔地點會增加地圖總地點數。既有四個副本保留原稿。
- **`players`**：一般 `2-4`；最終副本這類高難度的可以寫 `3-4`。
- **`unlock`**：建議設成「主題對應那一章的第 2 關」，讓玩家先在故事裡認識這個地區。

## 3. 劇情怎麼寫

- **一個副本一個小故事**：
  - `<before>` 交代「為什麼要去」，通常是城鎮居民來求助。
  - 每個房間的 `<enter>` 推進一點線索。
  - `<boss_half>` 讓首領說一句話。
  - `<after>` 收尾，並留一個鉤子連到下一個副本或主線。
- **用現有角色**：各城鎮的居民（老焰、小鐵、翠、楓、海斗、凪、雷歐、阿鈴……）會自動有頭像。新名字也可以用，會套預設頭像。
- **主線伏筆**：晨鐘、鐘舌、黑晶、白帆號、「讓黎明停止的人」。副本可以補充這些線索，但不要和 `story.txt` 的主線矛盾。
- 不要假設主角的職業或性別，用 `{玩家}` 稱呼。

## 4. 自動化量產（給 LLM 的提示範本）

```
請照 spellduel-unity/DUNGEON_FORMAT.md 寫 N 個新副本，加在 spellduel-unity/Assets/SpellDuel/Resources/dungeons.txt 的最後面：
- 等級分別是：Lv__、Lv__、……（波次與首領照第 2 節的表）
- 用固定地圖（[node] + next）：每條通關路線 6～9 場一般戰鬥，寶箱另計，終點是首領；可安排分岔但不能縮短到 6 場以下
- 依副本特色選用劇情人物與事件，不必每個都有護送、抉擇和任務；人物可放在某條岔路上，讓路線選擇有意義
- 每個地點都要有 <enter>，戰鬥地點盡量有 <clear>，首領要有 <boss_half>；人物要有 <meet>，抉擇人物每個結果都要有台詞
- 劇情和 story.txt 的主線呼應，用現有城鎮的居民；每句 60 字以內
- id 用英文小寫加底線，不能和現有的重複
寫完執行 python3 spellduel-unity/Tools/check_dungeons.py，直到 0 個錯誤再提交。
```

完整範例：`dungeons.txt` 裡的 `ash_mine`（灰燼礦坑）——分岔、寶箱、保護目標、抉擇、任務都有。

量產後：
- 副本入口的清單會自動分頁，每頁 4 個。
- 連線組隊的副本選單是兩個一排。
- 還沒解鎖的副本會顯示 🔒 和需要通關的關卡。


## 5. 固定出怪與目前支線路線

副本使用 `Combat.DungeonSpawns.cs` 的固定配置，不使用一般模式的隨機選怪／隨機出生點。
- 相同 `theme`、`wave`、隊伍人數、場地邊界，得到相同怪種、數量、出場順序與出生點。難度仍影響既有數值。
- 怪種遵守原本的主題解鎖表，每五隻中的第五隻優先安排遠程，從已解鎖種類依固定順序選取；尚未解鎖遠程時以該主題近戰補位。
- 場地周邊有 32 個固定位置，依波次與出場序號選位；與玩家／鏡頭位置、視線及戰鬥隨機數無關。
- 每次重進同一波都重設序號。同一波出現多次時會使用相同配置；人數增加仍沿用既有數量倍率。
- 首領種類仍由主題決定，出生點固定；首領房保留原本「先清小怪再出首領」流程。
- 固定的是遭遇配置，敵人出生後仍正常移動與戰鬥。主線及無盡模式保留原本出怪方式。

| 副本 | 每條路線一般戰鬥 | 最終首領波次 | 特色 |
|---|---|---|---|
| 餘燼鑄鐘坊 | 6 | 10 | 側廊護送小鐵、老焰的通風任務 |
| 霧燈記名徑 | 7 | 20 | 與楓的三向抉擇、翠的刻字拓片 |
| 白帆回聲礁 | 8 | 30 | 辨認航圖與假燈、海斗的抵達任務 |

格式檢查：`python3 spellduel-unity/Tools/check_dungeons.py`。
路線場次檢查：`python3 spellduel-unity/Tools/check_dungeon_routes.py`。
Unity 編輯器可執行 `SpellDuel > Audit > Dungeon fixed spawns`，檢查固定配置、重進、Boss 與一般模式隔離。

## 限時機關副本擴充

- `[dungeon]`可加`time_limit = 25`（分鐘正整數）、`traps = on`，省略不影響舊副本。目前機關規則只作用於`thousand_trap_gallery`。
- 地點`theme = vault`沿用角鬥場場景再疊加程序機關，不擴大全域故事主題編號。
- 新NPC角色`role = shop`使用meet/done；`role = lever`可寫三個option，結果為correct／wrong／neutral，對應done／enemy／third台詞，20秒由房主逾時選擇。拉桿與商店不暫停倒數。
- `escort`可加`optional = on`，倒下只失去該NPC的額外獎勵；省略則維持倒下失敗的原規則。
- 千機迴廊所有路線固定九場一般戰鬥加首領，寶箱不計戰鬥。`check_dungeons.py`會另外檢查這個副本的每條路徑。
